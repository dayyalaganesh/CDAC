# Mobile App Activity Log Analytics

## 1. Overview of the Use Case

A company collects daily activity logs from its mobile application, which are stored in Hadoop HDFS. The data engineering team uses Apache Hive to process these logs and generate critical business reports. 

The raw log fields include:
* **User ID**
* **User name** (often containing mixed casing that needs standardization)
* **Event type** (e.g., login, click, purchase, logout)
* **Device type** (e.g., iOS, Android)
* **Event date**
* **Session duration** (in minutes)

## 3. Hive Architecture & Workflow

The data flows through a structured big data pipeline:
1. **Raw Log Files:** Generated by the mobile application daily.
2. **HDFS Raw Layer:** Files are ingested and stored in Hadoop Distributed File System.
3. **Hive External Table:** Schema is applied on top of the HDFS files without taking ownership of the underlying data files.
4. **Hive Queries & Custom UDF:** HiveQL queries process the data, utilizing a custom Java UDF to standardize user names.

---

## 4. Key Business Reports & Insights

Using the architecture and sample data described above, the team can answer essential questions:

* **1. Which users generated application activity?**
  * Retrieves a distinct list of user IDs and names who interacted with the app.

* **2. How many users performed each type of event?**
  * `login`: 3 unique users (`U101`, `U102`, `U103`)
  * `click`: 2 unique users (`U102`, `U104`)
  * `purchase`: 1 unique user (`U101`)
  * `logout`: 1 unique user (`U102`)

* **3. What is the average session duration?**
  * Computes the overall average session length across all logged events.

* **4. Standardizing User Names via a Custom UDF**
  * Cleans up mixed-case names (like `"john doe"` or `"Bob Jones"`) into a uniform uppercase format (`"JOHN DOE"`, `"BOB JONES"`) for consistent reporting.
